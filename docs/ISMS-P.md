# 집보미 ISMS-P 기준 점검표

2026-11-03 작성. 집보미는 ISMS-P 인증 의무 대상이 아니다. 인증 기준(관리체계 16 · 보호대책 64 · 개인정보 처리단계 21, 총 101개)에 맞춰 **스스로 지키는 수준**으로 운영한다.
이 문서는 인증서가 아니다. 실제 인증을 받으려면 인증기관 심사와 아래 '운영자 과제'를 모두 갖춰야 한다.

상태: ✅ 구현 · 🟡 일부 · 📝 운영자 과제(문서·절차) · ➖ 해당 없음

## 1. 관리체계 수립·운영 (1.1 ~ 1.4)

| 항목 | 상태 | 내용 |
|---|---|---|
| 1.1 경영진 참여·책임자 지정 | 🟡 | 운영자 = 개인정보 보호책임자(김성환), 처리방침 제10조에 공개. 1인 운영이라 조직·위원회는 없다 |
| 1.2 자산 식별·위험 평가 | 📝 | 연 1회: 아래 '자산 목록'을 갱신하고 위험(유출·중단·변조)을 평가해 이 문서에 남긴다 |
| 1.3 보호대책 구현·공유 | ✅ | 이 문서 2·3장 |
| 1.4 관리체계 점검·개선 | 📝 | 연 1회 내부 점검(이 표를 다시 채움), 법 개정 확인 |

**자산 목록** — PC 1대(Windows, `Desktop\DEV\ZipBomi`), SQLite DB(`backend/data/zipbomi.db`, 백업 `backend/data/backups/`), `.env`·`data/llm_keys.json`·`data/admin_token.txt`(비밀값),
공개 주소(Tailscale Funnel `zipbomi.tail6bd481.ts.net`), 위탁: Google(Gmail 발송·Gemini), GitHub(소스, 비밀값 없음).

## 5. 사고 대응 (유출 의심 시)

1. 관리자 토큰 교체(`.env` ADMIN_TOKEN, OTP 비밀값) → 서버 재시작(관리자 세션 모두 끊김). 이용자 계정이 의심되면 관리 > 회원 계정에서 '모든 기기 로그아웃'.
2. 관리 > 관리자·접속에서 접속기록·위변조 점검 결과를 내려받아 보존(증거).
3. 개인정보가 유출됐으면 **안 날부터 72시간 안에** 정보주체에게 알리고(메일), 1천 명 이상·민감정보·해킹이면 개인정보보호위원회(또는 KISA, 118)에 신고한다.
4. 원인을 고친 뒤 이 문서와 README 에 경위를 남긴다.

## 6. 관련 설정

| `.env` | 뜻 |
|---|---|
| `ADMIN_TOKEN` | 관리자 로그인 토큰 (필수, 32자 이상 무작위) |
| `ADMIN_TOTP_SECRET` | 관리자 OTP 비밀값 — 넣으면 2단계 인증 필수, `X-Admin-Token` 헤더 로그인은 막힌다. `venv\Scripts\python tools\admin_otp.py` 로 만든다 |
| `ZIPGENIE_LOCAL_ADMIN` | 개발 서버만 1 (이 PC 접속을 관리자로) — 운영에서 켜지 않는다 |
| `ZIPGENIE_TRUST_ADMIN_IPS` | 등록 IP 를 토큰 없이 관리자로 — 운영에서 켜지 않는다 |
